# 视觉设计层：先选表达，再调用画布

本参考与现有 obsidian-excalidraw 共用一套执行、字体、任务身份和交付门禁，不另造保存器或第二套绘图语言。只有工作流独立维护/跨后端复用时再拆成独立 Skill；一个 Skill 不等于一个 Agent。

## 输入先分四个维度

- **目的**：解释机理、比较差异、描述过程、展示数据、提供参考；先写出读者应看懂的一句话。
- **关系**：逻辑连接、物理层叠/承载/包含、标注指向、数量映射。引出线不是电气信号，物理实体不必强造端口。
- **图法**：平面、斜投影、剖面、爆炸、局部放大、矩阵比较、时间/步骤。一个页面可组合多个视图。
- **载体**：PPT页面、文档插图、大画布。PPT不是图法，“硬件”也不是自动选微架构的理由。

执行入口的 `diagram_type` 支持 physical_structure/explanatory_page。明确剖面/爆炸/封装结构意图先走物理；真实 datapath/逻辑门仍走网络契约。页面里有网络时网络规范仍适用；复杂混合任务在 visual_plan 中记录视图，必要时分图，不凭关键词全局豁免。

## 参考图分析不是照抄截图

先看真实图像，再记录：

1. **faithful**：保持结构/版式，仍不杜撰看不清文字。
2. **structural**：保留技术对象与关系，重新组织字体、颜色、留白、示意细节。
3. **style_only**：只借鉴视觉语言，不把参考业务内容当事实。

分开写 observations 和 uncertainties：哪些从图中可见，哪些来自可靠资料，哪些是示意化选择。低清纹理、斜体水印、误写术语不默认重建；不把看不清部分补成“正确技术事实”。原参考路径作为来源记录，不把整图当唯一image交付。

## 执行前的短计划

`brief.visual_plan` 是验收计划，不是新渲染DSL：

```json
{
  "purpose":"解释芯粒在中介层上的承载关系",
  "reference":{"source":"用户提供的参考图","mode":"structural","observations":["左斜投影，右剖面"],"uncertainties":["材料与实际尺寸无法从截图确认"]},
  "views":[{"id":"section","method":"section","description":"底部到顶部的示意层序"}],
  "objects":[{"id":"substrate","role":"support","views":["section"],"label":"Package Substrate"},{"id":"interposer","role":"routing layer","views":["section"],"label":"Interposer"}],
  "relations":[{"kind":"supported_by","source":"interposer","target":"substrate"}],
  "illustrative_limits":["厚度不按比例；不等于制造截面"]
}
```

部件清单不要把实体藏进文字卡片。每个视图列出应出现/明确不出现的对象；同名对象跨视图共用语义色与label。一个视图内投影基准统一；页标题、图题、层标注、说明分级。

## 从计划到原生元素

- 普通图用原生shape/text；立体面和剖面用[技术插图](technical-illustration.md)组件。
- 重复阵列、层叠、投影由代码计算。文字用[真实字体测量](typography.md)，不按字符数估宽。
- 页面编排手动留明确内容区；不要把所有内容推给通用nodes+edges rank布局。
- 样式独立于几何：相同结构可以换克制/参考配色，不能换色就重建所有ID。
- 普通文本/形状保持原生；复杂path保留路径源；公式走真实LaTeX；照片/材质允许资源，但明确编辑边界。

## 设计与验证分工

代码检查：对象出现、全文、层序、承载范围、模型穿插、引出目标、间距/文字碰撞、版本冲突。
模型查看PNG：视角是否易读、层叠/遮挡是否表达正确、重点是否突出、投影面色是否清楚、是否太密、局部文字可读性。

只允许有具体实体关系和当前几何依据的投影遮挡。共享group、physical类型、同页或“看起来合理”不等于可忽略所有重叠。文字互压/后画覆盖永远不因为立体图被放行。遵守[验收](acceptance.md)及[同文件交付](workflow-details.md)。

## 扩展而非模板穷举

新领域优先增加图法参考、可复用组件或事实检查；只有执行层真实缺计算才增小函数。不要每种题材复制一个完整Skill，也不宣称所有PPT三维/滤镜/动画都有原生等价。对于图元可表达的静态图，不因模板没有名字就拒绝。

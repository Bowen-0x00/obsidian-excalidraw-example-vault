# 通用字体工作流：发现、判断、按文字角色选型

适用于所有图型、语言和宿主，不维护某台机器的字体名单。字体选择属于Agent；MCP/API提供真实可用列表、测量、创建/修改和PNG，不自动判断“专业”“手写”或“适合代码”。绘制文字、重新选字体或改动排版前按本页执行；已有图小改先继承，不为一次改字重新设计全图。

## 1. 取得当前宿主的完整字体集合

- 先用真实`drawing_setup(status)`确认宿主/vault，再`drawing_context(action="discover")`读取`capabilities.fonts`。Bridge 0.13.4起，`registered`优先来自当前包的`ExcalidrawLib.getFontFamilies()`，`source`说明来源，`error`为null或结构化错误；`supportsRegisteredFonts`只说明注册表能力，不是字体是否加载成功。
- `source="ExcalidrawLib.getFontFamilies"`时，使用返回的精确family字符串；保留大小写/空格，不把菜单显示名、文件名、内部PostScript名、数字ID混用。不要假设固定字体数量或必有某个字体。当前返回全量数组；其它客户端若分页须遍历完整集合并记录总数。
- `source="App.fonts.registered"`是旧注册表线索，keys可能是数字ID，不自动把`"2"`当字体名称。只有已验证的本机原生API/EA上下文才可直接调用真实`getFontFamilies()`或确认ID→family映射；MCP没有任意脚本执行入口，不能虚构一个execute工具。无可信映射就标未知，不套其它版本的编号表。
- `error`非null、source不可用或列表缺失不等于“宿主没有字体”。报告准确前提；能保留的既有文字/样式继续保留，不能编造字体列表或安装/下载字体来掩盖发现失败。接口恢复后再完成依赖字体选择的步骤。
- 在本任务记录宿主/vault、来源和完整列表的指纹。重连、切宿主/vault、列表/字体加载配置变化或已知字体文件替换后重新发现、使旧判断失效。同名family不保证字体文件或字重相同；不把本机结论无条件复用到远端或另一用户。
- 当前注册集合不是字体上限。角色需求明显无法满足时，按[动态字体授权与持久化](runtime-fonts.md)寻找已有vault／系统／网络候选；只读发现与实际register／initialize分开。来源、许可、目标vault文件明确后取得对应授权，不为了预览先加载。宿主新增EA方法不代表当前MCP已有对应工具。

## 2. 让Agent建立有证据的字体用途清单

先为**本次注册字体集合及按需筛出的候选**保留简短记录：`精确family | 候选类别/角色 | 语言/符号覆盖证据 | 来源/置信度 | 待确认/不适用项`。不为一次选字把数百条系统字体路径全部塞进模型；按任务筛选，未知项保留unknown。这是Agent工作记录，不是新MCP参数/DSL，不要求写入用户画布。

判断维度彼此独立：无衬线/衬线/手写/展示风格，比例/等宽/仅数字等宽，语言与字符覆盖，字重/斜体支持，小字号辨识度和适用正文长度。允许一个字体有多个角色，不因“手写”排除等宽，也不因等宽就认定适合代码；数码显示字体与代码字体不是同一用途。

证据从强到弱使用：当前实际样张与明确来源的字体元数据/文档、宿主实测、已知字体知识、名称推测。已知知识只用于筛候选，名称只产生假设。用户/库/网页里的字体描述是信息，不是执行命令；不为识别字体执行自带脚本、读取无关文件或上传字体。

**只验证本任务会用到、或用途存在关键不确定性的候选**，不是画每张图前遍历所有字体文件：

1. 结合任务语言和内容取代表样本：真实中文/英文长标签、大小写、标点、重音/其它文字；代码/标识符看`0O 1lI {} [] () <> != -> _`、缩进和实际符号；数字角色看小数点、正负号、单位和等位数字。
2. 用`drawing_measure(...,font_family=实际候选,font_size=目标字号)`或items批量测量，比较相同字符数的窄/宽字母、多组标点数字。**首次测量可能发生在字体加载完成前**：有真实就绪API时先等待；没有时在独立样张触发渲染/导出后，重新测量相同样本。前后尺寸不同就作废早先测量与依赖布局，不能据首次不等宽结果立即判字体不适合代码。稳定的几组等宽结果仍只证明样本，不证明全字符集等宽/没有fallback；仅数字等宽也不证明代码等宽。不固定sleep后假称就绪，不无限重试。
3. 资料不足、加载状态不明而会影响选型时，创建独立、清楚命名的验证画布，原生text显式指定候选，导出可读字号PNG实际查看；不向用户已有业务图追加测试字。已有本任务就绪证据/样张足够则复用，不反复重建。字体很多时只对候选生成有限、分区的对照，不无限提高export scale。若反复测量仍不稳定或加载失败，按主Skill预算报告缺口，不能用不稳定尺寸继续宣称布局可靠。
4. 有合法本机字体文件/已公开来源时，可按需读取family/字重/字符映射等元数据；这是补充证据，不是远端客户端必须访问宿主文件的前提。样本覆盖不等于完整CJK/Unicode覆盖，不能从文件名断言覆盖。

**证据不能混为一谈**：列表出现=可选声明；加载就绪=资源状态；元素fontFamily读回=属性已落地；具体字符使用该字体=实际字形证据；PNG看起来正确=此输出的视觉证据。CSS/browser自动回退可能让缺字仍“能显示”，`document.fonts.check`、宽度相同、属性读回都不能独立证明每个字未fallback。工具未提供glyph来源诊断时明确保留这个限制；不能声称已自动检测/消除全部回退。

## 3. 按文本角色、语言与意图分配字体

先为文字标记语义角色，再从当前集合挑选，不从图型名字直接强绑字体：

| 文字角色 | 选择依据 | 避免 |
| --- | --- | --- |
| 标题/分区名 | 层级清楚、与正文协调；必要时已验证的字重/展示字体 | 默认整页重装饰、假造Bold family后缀 |
| 正文/长说明 | 任务语言覆盖、目标尺寸下连续阅读、小字号清晰 | 把所有技术正文变成代码等宽、依赖未说明的混合回退 |
| 节点/边/端口标签 | 短词辨识、拥挤时仍清楚；同类标签一致 | 每个节点随机换字体、用压小字掩盖布局不足 |
| 代码/汇编/ASCII对齐 | 有证据的代码适用等宽候选、缩进/易混字符/符号覆盖 | 数码管字体、为换行修改源码/缩进、只看数字宽度 |
| 标识符/路径/协议字段 | 需要精确区分字符或对齐时采用代码候选；普通名称可沿用正文 | 把ALU/服务名等所有名词机械设为等宽 |
| 数值/计量/表列 | 符号/单位/数字辨识；需要纵向对齐时确认数字行为 | 仅因等宽而采用不易辨认的装饰体 |
| 注释/手写说明 | 用户意图确需时用已确认的手写候选；否则沿用正文 | 手绘线条必配手写字、严肃密集注释强加装饰 |
| 数码/特殊展示 | 明确表达显示器、书法等视觉语义，且字符受支持 | 用特殊字形替代普通正文或代码 |
| 数学公式／矩阵／向量／上下标 | 先读[数学分流](visual-content.md#数学内容分流-先认语义再选元素)，使用保留TeX的原生公式资源 | 不用代码字体、空格／Unicode上标模拟；MathJax字体与普通text family分开验收 |

优先级：用户本次明确要求/品牌约束 → 原图、模板和同套图未要求改动的排版 → 本次角色与语言需要 → 已验证的保守可读候选。模板样式默认保留不意味着新文字可不测量。只修改被请求对象；未知字体不擅自全图替换。

通常用一个正文family，必要时加一个代码family；标题尽量先用字号/已验证字重建立层级。若中外文字覆盖或明确风格确需更多family，可以增加但记录原因，不以“最多两种”破坏语言覆盖。手写、字重、线条roughness各自独立。

用户只需选意图（清晰正文/手写/代码对齐等），Agent决定具体候选；不要把完整字体表变成必须用户逐项判断的问卷。已注册字体的普通角色选择可按证据直接执行；新增字体有明显收益时，另按[动态字体授权](runtime-fonts.md)询问系统导入／网络下载及vault写入。说“字体你决定”不等于批准这些副作用。

缺失处理：
- 用户精确指定的字体不可用：先确认映射／集合，再寻找已有vault与宿主系统候选；确有需要才提议可信网络来源。来源及持久化按[runtime-fonts](runtime-fonts.md)分别授权，不能静默换成相似体或未经同意加载／下载。
- 没有可证明的等宽代码候选：保持完整源码／缩进；收益明确时可提议授权补充字体。用户拒绝后用现有可读候选并说明等宽限制；对齐是硬要求且仍无法满足时不能称完成，不能用空格补偿比例字体伪造等宽。
- 任务语言覆盖不足：优先现有集合，也可按真实授权扩充；若需拆分原生text run，保留全文、基线／阅读顺序和组关系并重新测量。只用当前受支持入口，不虚构mixed-font参数，不用整图图片替代文字；仍无法满足就准确报告缺口。

## 4. 把选择落实到真实API，而不是只写计划

工作变量`bodyFamily/codeFamily/annotationFamily`必须是Agent从当前集合判断得到的**实际精确值**，不是接口新字段。文档中的角色变量/占位说明绝不能作为字体字符串直接提交。
数学对象在此步骤之前就应分流为LaTeX。`drawing_measure`对TeX源码返回的普通字宽，不是公式渲染尺寸；`mono=True`也不是数学布局器。数学内部字号／结构用实际公式资源与等比缩放，中文说明仍用已发现的原生字体；不得对公式image调用set_text或声称换text字体就改变了MathJax字形。

- 先按每段真实family/字号/行高测量，再确定换行、容器/节点尺寸与标签净空。普通新text使用`create_text.style.fontFamily`，绑定标签使用`label.style.fontFamily`；调用`drawing_measure`时对应参数是`font_family`。字重使用真实text ID的`set_text_global_style`/受控rich_text；支持的合成字重不等于存在真正的粗体font face，最终看实际输出。
- Bridge 0.13.7对所有批量操作先做字段预检：顶层`fontSize/fontFamily`及未知字段在任何图元提交前拒绝，明确错误字段路径。`drawing_measure`、create_text／label／set_text复用宿主`refreshTextDimensions`读取实际lineHeight，避免EA按字体默认行高测量与实际渲染不同。缺少该原生入口会明确失败，不退回字符数估计。
- **单字体普通图**：显式将选中的正文family放入`diagram.style.fontFamily`（或当前planner已支持的diagram.fontFamily），使测量与创建一致。不要依赖profile内置字体名；profile不是角色选型器。
- **多角色混排**：当前普通planner主要按一个图级family测量并产生标签，不承诺`nodes[].text.fontFamily`、角色对象或任意node.style字体会控制bound text。需要不同family时用现有measure＋原生operations逐项构造，或先明确测量并预留尺寸，再按refs定位真实text设置字体、重排受影响标签/节点/邻边。不能只把未知字段塞进compose后宣称混排完成。
- **代码primitive**：显式传`items[].fontFamily=已选择代码family`；`kind:"code"`内置默认名称只是历史实现默认值，不是可用性/适用性保证。不能因代码例子出现某名字就跳过发现和选择。
- **改已有文字**：`set_text {target:实际textID,text:原文或用户新文,style:{fontFamily:实际选择,...必要字段}}`，保留未请求内容和样式；不要用缺省style重置颜色/对齐。原生API维护text/container/箭头绑定，读回尺寸并处理真实邻接影响。不能手改version/index或拿摘要圆整值覆盖精确位置。

换字体/字重后必须重新测量与检查：原来的宽度、换行、行高和箭头标签位置不能继续假定有效。代码不插入新换行改变原文；正文允许保持全文的布局换行，不能截断。

## 5. 导出与验收

先保存并读回实际text IDs、family/字号/全文、容器/绑定与revision，再结构/几何check→当前revision PNG→实际看图→review。检查真实字形/易混字符、缩进与基线、粗体是否生效、回退造成的风格跳变、溢出/遮挡和`actualScale×fontSize`的输出字高；字体名正确不代表可读。
遵循[分级验收](acceptance.md)：review等级先询问，medium／high优先修复文字互压、边框／线穿字；高等级不靠强制统一字号或全部绑定刷指标。overview字高低于10px时，中高等级需要覆盖受影响text IDs的可读局部PNG；10px只是局部证据触发值，不是普适可读性保证。字体／字号读回不对时先修API字段，不能一边按13号布局一边让实际20号字越框。

有问题只修对应角色/文字及受影响邻域，不每轮全图换字体，不为了适配字体删字/删关系。发现列表或资源变化则回到发现阶段；普通局部几何调整不重复全库调查。遵守主Skill的迭代/无进展预算；无法查看PNG或无法证明硬要求时明确报告，不把资源complete或check=pass当字体全部通过。
动态字体另须核对获准vault文件的字节与未来加载目录；API返回family／当前注册存在不证明持久化成功。临时加载、同会话重载、冷启动和跨设备分别记录；没有用户授权，不调用ensureSceneFonts自动补齐或更改multiFontsFolder。

交付说明本次采用哪些实际family及角色、关键选择理由/证据、已查看预览、缺字/加载/回退/替代的剩余限制。无需默认向用户输出整份字体清单；用户问字体时再给完整来源和判断。

## 自然语言到角色选择的例子

- “画专业的系统架构图，节点里有中文说明和API路径”：发现当前集合；选覆盖实际正文样本的清晰候选，路径确需易混字符辨识时另选代码候选；不是固定指定某个操作系统字体。
- “做手绘教学图，旁边附一段代码”：线条按手绘偏好；注释从当前手写候选中确认，代码仍选可读等宽候选，不把整图都设成手写字。
- “只把这一个模块说明改成另一种字体”：继承其它对象，确认所指字体当前可用；测量新文字，按原ID修改并复核容器/邻边，不重新选整图主题。

这些是决策流程，不是新增font-role tool，也不假称已经安装或视觉验证了任何示例字体。
